Agents can only act on your behalf if they are aligned with preferences you may not be able to spell out upfront.

01 / the problem

1/ Why Alignment Is Hard: Socially Embedded Tasks

In a socially embedded task, an agent acts on your behalf, toward other people, over weeks. Alignment is what makes delegating it possible: the goal is to offload as much as possible while keeping control. But alignment is hardest exactly here, in three ways. We study this in a concrete setting: organizing a university seminar series over email.

“Who should I follow up with today?”

C1 · Hard, high-stakes task

Weeks of tracking, follow-ups, and edge cases across many people, and every action lands on a real person. You can't unsend an email.

NeedOffload, but keep control

“Who's been scheduled? How many emails have I sent asking for Lydia's availability?”

C2 · Opaque agent

Users can't see where things stand or why the agent wants to act, so they can't judge a proposal before it goes out.

NeedInspectability

“A faculty member and a student both say they can only do 9/28…”

C3 · Hidden intent, hard to elicit

Tacit norms (when (not) to act, when (not) to ask, what tone to use) surface only when users see the agent act, and keep evolving.

NeedElicit intent over time

+ And you can't practice on real people.

Users discover what they want by watching the agent act, but every trial run reaches a real inbox. So alignment can't be specified upfront; it has to be reached through repeated interaction, and that needs a safe place to repeat.

Fig. — Overview
Alignment as something you do over repeated runs

From an initial setup—a goal, simulated personas, and seed policies and templates—users iteratively align the system by reviewing plans, approving actions, handling edge cases, and refining artifacts.

  • Each run produces a finalized speaker-slot allocation and a set of user-aligned artifacts: policies, email templates, and stop hooks.
  • Those artifacts persist and transfer to future coordination tasks, so alignment compounds instead of restarting.
  • Grounded in distributed cognition: the system takes on tracking and drafting so the user can focus on judgment at points of uncertainty.
Fig. — Day-by-Day Workflow
Policy-guided planning with human oversight and simulated respondents

The coordination agent runs a day-by-day loop against LLM-simulated speakers, each with their own persona.

  • Inputs are the organizer's goal, seminar slots, speaker personas, and a toolbox of callable functions.
  • Each day the agent summarizes state, finds relevant policies, proposes a plan, and drafts actions for the user to approve.
  • When a reply falls outside known policy, such as a request to present over Zoom, the agent flags the edge case to the user.

Summary

Delegating socially embedded work is not a one-time specification problem. Users need to offload while keeping control (C1), inspect what the agent is doing (C2), and have their intent captured as it emerges (C3), with a safe place to practice before real stakes.

02 / system

2/ DoubleAgents: A Distributed-Cognition System

We draw on distributed cognition (Hutchins, 1995): in hard sociotechnical systems like a cockpit, no single person holds all the cognition. It is spread across people and artifacts through three mechanisms: state tracking, representation, and adaptive policies. DoubleAgents maps each mechanism to one component that answers one challenge, plus a simulation mode for rehearsing before going live.

C1 · Offload, but keep control

State tracking → Coordination agent

Tracks every thread over weeks, plans next steps, and proposes actions. The user approves before anything is sent, and the agent flags edge cases it isn't sure about.

e.g., plans who to reach out to and drafts the emails; you approve.

C2 · Inspectability

Representation → Dashboard

Temporal, social, and procedural views make task state and the agent's reasoning legible at a glance, so users can judge a proposal before it goes out.

e.g., time constraints, availability collected so far, email history.

C3 · Elicit intent

Adaptive policies → Policy module

Every user edit becomes a reusable artifact, so intent is captured as it emerges and carries over to future coordination tasks.

e.g., organizing policies & strategies, email templates, when to escalate (stop hooks).

+ A safe place to repeat → Interactive simulation

LLM-simulated speakers compress weeks of coordination into minutes, so users can exercise all three components and surface edge cases before real stakes. It works like unit testing, except that correctness is user-specific.

Fig. — The Interface
Policies, a coordination agent, and a dashboard

A snapshot of DoubleAgents coordinating four speakers across seminar slots.

  • Coordination agent (state tracking, C1): tracks state, plans next steps, suggests actions, and surfaces the policies guiding each decision.
  • Dashboard visualization (representation, C2): externalizes assignments, timelines, and communication history so the user can read the situation at a glance.
  • Policies (adaptive policies, C3): encode evolving user preferences and procedures, and can be added, edited, or deleted as the user learns what they want.
  • User edits are turned into reusable coordination policies, email templates, and stop hooks that improve behavior over time.
Fig. — Step by Step
Plans, actions, emails, and flags the user can review

Pop-ups for a generated plan, the actions that follow it, a drafted email, and an edge-case flag raised when Prof. B asks about Zoom.

  • Every plan and action is shown with its rationale before anything is sent.
  • Flags hand the decision back to the user, whose answer becomes a pending action the system can carry out.

Summary

Rather than asking users to write the perfect prompt, the system lets them correct it in context. Every correction is captured as an artifact the agent can apply next time.

03 / two-day study, n=10 · three deployments

3/ Study, Deployments & Discussion

We evaluated DoubleAgents through a two-day in-lab interactive simulation study (n=10), three real-world deployments, and a technical evaluation.

Fig. — Comfort Over Time
Comfort with delegation grew, but not evenly

Average comfort with automating (a) planning and (b) execution across sessions (1–7).

  • Planning comfort rose across all four sub-tasks, from roughly 5/7 before to around 6.5/7 after.
  • For execution, comfort with the AI only drafting emails was already high and rose to nearly 6.8/7.
  • Comfort with the AI drafting and sending started far lower (around 3/7) and stayed lower, reaching about 4.3/7.
  • Clarification emails showed no significant change: participants still wanted control at points of uncertainty.

Deployments

Simulation prepared organizers for the real thing

Two organizers used DoubleAgents for real email-heavy coordination. Both attributed their willingness to offload to explicit, editable policies and templates that made the agent's reasoning legible, and used simulation with real invitee names and persona-specific edge cases to refine them first.

"DoubleAgents was really helpful and saved me a lot of time… The simulation part cannot be skipped." — Q1, deployment organizer

Deployment still surfaced unanticipated dynamics that needed ongoing policy and tone adjustments—as Q1 put it, “real life is super complex.”

Discussion
What this means for alignment systems
  • Distributed cognition works as a design lens. Comfort and reliance tracked the three components, each answering one challenge: a state-tracking agent (C1), legible visualizations (C2), and adaptive policies (C3).
  • Control stays at uncertainty. Edge-case flagging and context-dependent actions are where people still wanted to decide.
  • Reliance grows with legibility. “I would intervene more at first but if it can demonstrate that it's consistently able to do it correctly, I'm going to let it act on its own on my behalf more autonomously” (P2).
  • Interactive simulation is a methodological testbed for rapid iteration and alignment testing of agentic systems before live use.

Contributions

  • A distributed cognition approach to human-agent alignment in socially embedded tasks.
  • DoubleAgents, which maps each distributed-cognition mechanism to a component: state tracking → a coordination agent (offload, but keep control), representation → a dashboard (inspectability), and adaptive policies → a policy module that turns user edits into reusable alignment artifacts (elicit intent).
  • Interactive simulation as a methodological testbed, evaluated in a two-day study (n=10), three deployments, and a technical evaluation.
